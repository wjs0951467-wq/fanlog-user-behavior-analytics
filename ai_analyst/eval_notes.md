검증 도구와 상태는 "확인 방법" 열에 행마다 적는다. "DBeaver 직접 검증"이라는 표현은 DBeaver 로 확인한 행에만 쓴다.

기준: 활동 상태(휴면 / 이탈 위험 / 활동 중) 질문의 기대값은 모두 탈퇴자 제외 기준이다. (DESIGN.md 9장)
검증 상태 (2026-11-11): 마지막 날짜 기준 탈퇴자 제외 값은 active 1,643 / at_risk 75 / dormant 3 이다.
(전체 기준 1,670 / 77 / 3, 그중 탈퇴자 27 / 2 / 0)
- active 1,643: notebooks/churn_validation.ipynb 의 SQL_POPULATION_CHECK 로 검증 (Claude Code 실행).
- at_risk 75: 아직 독립 검증 없음(추정). 전체 77 에서 탈퇴 2 를 뺀 값이고, 모델이 낸 숫자와 일치한다는 것은 독립 검증이 아니다.
- 이 줄은 이전에 "DBeaver 독립 검증"이라고 적혀 있었으나, DBeaver 로 확인한 것이 아니어서 고쳤다.
"결과" 열은 Day 1 버전(LLM 1회 호출)으로 확인한 것이다.

## Day 2 버전 재확인 (2026-11-11)
재시도 루프 + JSON 출력(assumptions) + 요약이 들어간 Day 2 버전으로 위 6문항을 다시 실행했다.
- 결과: 6/6 일치. 재시도 0회(모두 첫 시도에 성공), JSON 파싱 실패 0건, fallback 사용 0건.
- 호출 수: 총 7회 (휴면 질문 1개는 요약 포함 2회, 나머지 5개는 요약을 끄고 1회씩).
- 이탈 위험 / 활동 중 질문은 "(탈퇴자 제외)"를 붙이지 않고 물었고, 모델이 기본 규칙대로 탈퇴자를 제외해 assumptions 에 명시했다.

### 이 6문항의 성격: 개발용 질문
이 6문항은 시맨틱 레이어를 개발하며 정의를 맞출 때 사용한 "개발용 질문"이다.
정의를 이 질문들에 맞춰 고쳤으므로 6/6 은 일반화 성능의 근거로 쓰면 안 된다.
Day 5 평가셋에는 개발 중 한 번도 쓰지 않은 "보류 질문(held-out)"을 따로 넣어야 한다.

### 한계
재시도 / 거짓 거절 교정 / 접속 오류 중단 경로는 실제 API 로 실행된 적이 없다.
6문항이 모두 첫 시도에 성공했기 때문이며, 이 경로들은 mock 테스트(tests/test_text2sql.py)로만 검증됐다.

## 함정 케이스 (발견한 문제)
- is_closed_funnel_complete = true 로 필터하면 전환율이 100%가 나옴. 시맨틱 레이어 힌트가 틀렸던 것을 데이터 검증으로 발견해 정의를 고침.
- profile_db 가 뷰를 빠뜨려 모델이 "테이블이 없다"고 답함(거짓 거절). 프로파일링을 수정하고, 빠진 테이블이 있으면 에러를 내도록 보강함.
- 내가 센 정답(77, 1,670)은 탈퇴 사용자를 포함한 값이었고, 모델은 시맨틱 레이어 규칙대로 탈퇴자를 제외한 값(75, 1,643)을 냈음. 기준 불일치를 발견해 정답표를 수정하고, 답변에 가정을 명시하는 기능을 개선 과제로 기록함.
